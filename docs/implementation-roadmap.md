# 專案實作時程與里程碑

本工作路線為團隊共同執行，與正式提案中六週實作順序一致。各項產出只有在完成並保存實際證據後才標示為已驗收。

| 階段 | 工作 | 可驗收成果 |
| --- | --- | --- |
| W1 資料盤點 | 官方 API、CSV schema、臺中測站篩選、歷史覆蓋與異常檢查 | 資料字典、來源快照、EDA、品質表 |
| W2 ML 預測基線 | 特徵工程、Persistence／Seasonal Naive、Ridge／RF／XGBoost、時序回測 | 基準模型與候選模型比較表及固定設定 |
| W3 AI Agent 核心 | 工具白名單、查詢解析、官方規則、引用／時間檢查與錯誤降級 | 工具合約、執行軌跡、單元測試 |
| W4 網頁系統整合 | React／Next.js 介面、FastAPI、來源卡片、時距／風險圖表 | 可操作的端到端 Demo |
| W5 系統測試與評估 | 模型分組、消融、至少 30 題 Agent 測試、性能與限制 | 可重現測試報告與錯誤分析 |
| W6 期末成果交付 | 版控、README／DESIGN 更新、安裝重現流程、完整簡報及影片 | GitHub、Final PPT（21 頁以上）、YouTube 影片（超過 10 分鐘）、實驗結果與結論 |

**優先順序**：取得與核對資料 → 可重現的基準模型 → Agent 工具呼叫（Tool Calling） → 端到端網頁介面 → 實驗評估 → 期末成果交付。

**專案里程碑的主要阻擋條件**：歷史監測資料品質不足、預測特徵存在資料洩漏、官方規則未能核實、系統回覆無來源、以及把 6h 模型結果誤用於較長時間預測。

## 與 Proposal 交付的關係

本專題由 3 位組員共同完成，**目前不預先規劃個人分工**。上表是後續實作里程碑，不是 Proposal 階段新增的繳交項目。

Proposal 階段僅需確認：提案報告書、提案簡報、正式 GitHub Repository 及 `DESIGN.md`。完成遠端儲存庫建立後再確認教師可讀取，後續開發才依實際需求使用 GitHub Issues／PR 追蹤。
